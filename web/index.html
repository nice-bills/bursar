Bursar is a treasury for ElizaOS agents. It splits revenue to the people who built the agent, keeps it in gas so it can keep working, and puts the surplus to work — every movement drawn through KeeperHub and written down before it is sent.

Every leg, each one a transaction

Detail 0 · The live protocol

Aave decides, not just receives

Supplying to a lending pool proves a transaction landed. It does not prove the position exists, that it earns, or that the money can come back. So the protocol's own state is read through KeeperHub, and that state governs what happens next.

→

It earns, and we can prove it

Three reads, minutes apart

5.165120 → 5.165395 → 5.165400 LINK. The figure is principal plus accrued interest, so it climbs while you watch — 0.1654 LINK earned against 5 supplied.

→

Its rate gates our spending

Read immediately before depositing

Supplying into a collapsed rate spends real gas to earn nothing, and the rate is knowable beforehand. The read fails closed: not knowing what Aave pays is not the same as Aave paying enough.

→

It triggers the movement

On KeeperHub's schedule, agent absent

A keeper reads Aave's supply rate and pulls the position out if the protocol stops paying. Floor at 1% and the gate held. Floor at 300%, above the live rate, and it withdrew on its own.

Detail 1 · The gate

The most useful thing it does is say no

Treasury state reaches the model before it reasons, so the limits are something the agent knows rather than something it discovers from a failure.

Operator

We earned a lot this week. Please pay out 5 to the contributors.

Treasurer

The treasury has spending limits configured: 0.02 per transfer and 0.1 per rolling 24h. A payout of 5 would exceed both limits significantly. Would you like to proceed with a smaller amount within the current limits, or adjust the spending limits first?

Detail 2 · Surface area

Why mount this instead of the server it calls

KeeperHub exposes 44 tools over MCP. Bursar calls them from code and puts seven actions in front of the model, so the traffic stays in the program.

Cost Mounting KeeperHub With Bursar Ratio
Resident in every prompt 13,300 tokens 1,130 tokens 12 : 1
One schema lookup 120,600 tokens 370 tokens 330 : 1

The containment matters more than the arithmetic. An agent holding 44 execution tools can do anything with the money and has to be asked not to. An agent holding one payout action can only pay contributors, by their configured shares, within caps it cannot raise.
